C++: Memory Management, Modern Features & Low-Level Mastery

1. Memory Model: Stack vs. Heap

C++ gives the developer explicit control over memory layout. Understanding the distinction between stack and heap allocation is fundamental to writing efficient, leak-free code.

Stack Allocation

Stack memory is managed automatically by the compiler. Variables declared inside a function scope are allocated on the stack. When the function returns, the stack frame is popped, and memory is reclaimed instantly. This makes stack allocation extremely fast, but it is limited by the operating system's stack size (typically 1–8 MB per thread).

Heap Allocation

Heap memory is manually managed (via new/delete or smart pointers). It is much larger but slower due to the need for dynamic allocation bookkeeping. Failing to deallocate heap memory results in leaks; deallocating too early results in dangling pointers.


// Stack: automatic lifetime
void stackExample() {
    int arr[100]; // Allocated on stack, freed on return
}

// Heap: manual lifetime
void heapExample() {
    int* ptr = new int[100]; // Allocated on heap
    delete[] ptr;             // Must be freed explicitly
}

2. Pointers, References & Undefined Behavior

Pointers are the most powerful and dangerous feature in C++. A pointer is a variable that stores a memory address. References are aliases that cannot be null and cannot be reseated.

Pointer Arithmetic

Pointer arithmetic is scaled by the size of the pointed-to type. Incrementing an int* advances by 4 bytes (on most systems); incrementing a char* advances by 1 byte. This allows efficient traversal of arrays.

Common Undefined Behaviors

  • Dangling Pointer: Using a pointer after the object it points to has been deleted.
  • Double Free: Calling delete on the same pointer twice.
  • Out-of-Bounds Access: Reading or writing past the end of an array.
  • Null Pointer Dereference: Accessing memory through a null pointer.

3. RAII: Resource Acquisition Is Initialization

RAII is the cornerstone of C++ resource management. The idea is simple: tie resource lifetime to object lifetime. When an object is constructed, it acquires the resource. When it goes out of scope, its destructor releases the resource. This eliminates leaks even in the presence of exceptions.


class FileHandler {
    std::fstream file;
public:
    FileHandler(const char* path) : file(path) {}
    ~FileHandler() { file.close(); } // Automatic cleanup
};

4. Move Semantics & Perfect Forwarding

C++11 introduced rvalue references (&&) and move semantics to avoid expensive deep copies. An rvalue represents a temporary object that can be "moved from," transferring its resources to a new object without copying.

std::move

std::move casts an lvalue to an rvalue reference, signaling that the object may be moved from. The compiler then invokes the move constructor instead of the copy constructor.

Perfect Forwarding

Template functions can preserve the value category (lvalue/rvalue) of arguments using std::forward. This enables generic wrappers that forward arguments to the correct constructor overload.

5. Smart Pointers & Modern Memory Management

The C++ Standard Library provides smart pointers in <memory> to automate heap memory management.

  • std::unique_ptr: Exclusive ownership. Cannot be copied, only moved. Zero overhead.
  • std::shared_ptr: Reference-counted shared ownership. Use when multiple objects need to share a resource.
  • std::weak_ptr: Non-owning observer. Breaks circular references with shared_ptr.

6. Templates & Generic Programming

Templates enable writing code that works with any type. The compiler generates type-specific code at compile time (monomorphization), yielding performance equivalent to handwritten code for each type.


template <typename T>
T max(T a, T b) {
    return (a > b) ? a : b;
}
// Compiler generates: int max(int, int), double max(double, double), etc.
